# Desktop design

Reading this as a Windows download utility for daily use, with a calm, precise visual language. This is a visual overhaul that retains the account, folder, input and queue workflow.

The requested `design-taste-frontend` skill informs the audit, typography, hierarchy, spacing and review. Its marketing-page patterns are outside this native desktop app's scope. The implementation uses Microsoft's .NET 10 WPF Fluent resource dictionaries, not web controls or a simulated Fluent skin.

- **DESIGN_VARIANCE: 4.** A 246 px setup panel keeps configuration separate from the larger working area. The brand icon and name stay intact.
- **MOTION_INTENSITY: 2.** Native hover, pressed and focus feedback. No entrance, looping or decorative animations.
- **VISUAL_DENSITY: 5.** Compact source input and an expanding queue. The setup panel scrolls on short windows; the queue scrolls when rows or columns need more space.

The previous screen stacked account, folder and a large input area above the queue. Repeated bordered buttons competed for attention, system controls looked inconsistent and uppercase labels dominated. The revised screen uses sentence case, Segoe UI Variable with a Segoe UI fallback, a single cobalt brand accent and semantic status colors. Primary actions use the native accent style; utility actions are quiet and queue clearing is separated from selected-row actions. Row actions show only the operations available for that state, with an accessible, tooltip-labeled remove icon.

Spacing follows a 4/8/12/16/24/32 scale, and every tab uses the same 16 px inset for its header, table cells and footer. The shell is flat: one surface color, a sidebar divider, table separators and transparent section backgrounds. Only the folder-tree pane and the sidebar tip use the subtle surface. Workspace tabs are pivot-style: muted labels, ink when selected, an accent underline and a divider under the strip. Tab headers show a live summary (queue counts, tracked remote torrents) in one shared section-title style instead of repeating the tab name. Quiet actions keep their semantic color on hover and fade, without a fill, when disabled. File types use soft accent icon chips in the list and grid. File tiles have no resting card fill or outline; hover, selection and keyboard focus use an 8 px radius, and selected tiles show a filled check badge. Native controls retain their standard focus states. Light and dark palettes share semantic resource names. System appearance changes are observed; manual appearance choices and language are saved. New or missing language preferences default to English, while an explicit Vietnamese choice remains valid.

WPF checks render English and Vietnamese in both appearances, an empty queue and compact layouts. They also verify first-launch language, saved preferences, selection actions, visible primary controls and translation placeholders. Screenshots use labeled sample queue data without network transfers.

The working area separates **Torrent files** from **Download queue** using native tabs. Paste, file picking and drops only fill the batch input; **Add to library** explicitly starts inspection, with inline progress and cancellation. A compact input stays visible on every tab with no expand/collapse control. Typing and staging sources remain available during queue processing and inspection. Manual import can run alongside existing downloads; only the submitted input prefix is removed on success, preserving newly entered sources. Inspection obtains metadata without selecting remote files. A folder tree scopes recursive filename/path search; a video toggle filters common video extensions. List checkboxes and grid tiles share selection, count/size and queue actions. Search/folder changes clear selection; view switches preserve it. Empty results and per-source inspection failures remain visible.

Users can search unwanted files, select results and remove them from the virtual library. Removals store excluded IDs per source; metadata, remote torrents, local files and existing queue entries remain intact. Empty folders disappear from the tree. Undo restores removal batches within the current session. Exclusions and the List/Grid preference persist across restarts. **Queue all remaining (N)** queues the entire pruned library, including files outside the active search or folder, while skipping already queued files. The count and tooltip make this scope explicit. Delete, Ctrl+A and Ctrl+Z operate within the file view.

The folder tree supports a dedicated **Remove folder** action, a right-click command and Delete. Folder removal uses the exact source and directory boundary and includes descendants outside the current filters. Torrent roots have a persisted hidden flag so even roots without metadata can be removed. Sources with no visible files are omitted from the tree. File removals and root removals share one Undo stack; restoring a root keeps earlier file exclusions. Folder actions preserve queue work, local files and remote IDs.

The queue stores explicit selected file IDs. Resume keeps them and preserves established local paths. New selections from the same source use a separate remote torrent once started. The downloader checks selected-link mapping and rejects combined or mismatched links before transferring the affected file. Older saved queues keep their original all-files behavior. Browser metadata and unfinished inspection IDs are persisted alongside the queue.

**New batch** clears all virtual sources, excluded-file Undo history, pending input and filters in one action. It keeps existing queue work and local files. A persisted registry captures remote IDs from both metadata inspection and queue processing before either local list is cleared.

**Real-Debrid torrents** is a separate management tab that lists the token's whole account (`GET /torrents`, paged), not only IDs the app created, so torrents added on the website appear and ones deleted elsewhere disappear. Rows show name, exact ID, size, a colored status pill with progress, date added, and an **In queue** tag when a queue entry uses that ID. The list loads when the tab opens or on **Reload**; a newer load cancels an older one, and a token change clears it. A review step freezes the selected IDs and displays the consequences before the explicit remote-delete confirmation; Reload is disabled while reviewing or deleting. Before any DELETE the token's account must match the account the list was loaded for. Only tasks linked to those exact IDs are stopped, with writers awaited before DELETE; successful IDs leave the list together with their queue rows, failed rows stay with their error for retry, and local complete/partial files remain intact. Canceled/ambiguous requests stay listed, and failed DELETE requests are not replayed automatically except explicit rate-limit responses. The app still records the IDs it creates so queue/library history survives new batches.

Queue details expose the remote seed count and speed when available. A remote `downloading` response with zero seeds and zero speed is presented as waiting for sources. File selection and local-transfer state are preserved while waiting, and no local download starts before Real-Debrid supplies links.

List rows, file checkboxes, grid tiles and remote-torrent rows share an anchor-based range selector. Shift extends from a stable anchor; Ctrl+Shift adds ranges and Ctrl toggles individual items. Range order comes from the displayed collection view, so sorting and filtering remain correct. File anchors survive view/language changes and reset when the search/folder scope changes. Model selection drives row highlighting in one direction to avoid stale native DataGrid selections overwriting changes after sorting or switching views.

Disabled data grids keep the surface color (Fluent animates them to `ControlLightColor`, which each theme defines), and checkbox columns use a narrow cell inset so the 30 px Fluent checkbox is not clipped. The application dictionary is `Styles.xaml` itself, and a theme change reassigns it so already-open windows refresh. App confirmations and information messages use a shared WPF dialog with the same dynamic surface, text, divider and control resources as the main window. Its caption uses the active dark-title-bar setting. Confirmations keep Cancel as the default and support Escape; information messages use one Close button. Render checks cover both themes, and modal checks exercise the real clear-queue Cancel and Confirm paths using isolated settings.

Reference: [Microsoft WPF Fluent theme guide](https://github.com/dotnet/wpf/blob/release/10.0/Documentation/docs/using-fluent.md).
